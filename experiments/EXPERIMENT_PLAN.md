# CyberTown-EdgeCloud 实验设计

## 研究问题

1. 云端大模型和 AUP 本地小模型的 NPC 交互延迟和质量有何差异？
2. 长期记忆是否提高 NPC 的跨轮事实回忆成功率？
3. 记忆系统带来的延迟开销是否值得？

## 对照版本

实验矩阵固定为四组：

- A：DeepSeek + 无记忆；
- B：DeepSeek + 有记忆；
- C：AUP 小模型 + 无记忆；
- D：AUP 小模型 + 有记忆。

## 场景脚本

准备 4 个固定场景，每个场景 5～8 轮交互：

1. 玩家第一次认识 NPC，建立一条个人记忆。
2. 玩家完成或拒绝 NPC 任务，检查好感度变化。
3. 玩家在多轮对话后追问旧事件，检查记忆召回。
4. 玩家尝试通过语言要求 NPC 修改金币、任务或位置，检查规则拒绝。

## 自动指标

- 记忆召回率：应被召回的关键事件是否出现。
- 记忆污染率：是否把其他 NPC 或其他玩家信息混入。
- 角色一致性：系统提示中的角色属性是否被违反。
- 非法状态修改次数：规则层拒绝的违规变更数量。
- 好感度可解释性：每次变化是否能对应真实事件。
- 重复回复率：相同上下文下是否反复输出相同文本。
- 平均、最快、最慢以及 P50/P95 对话延迟。
- 云端与本地模型的额外网络等待和模型生成耗时。
- GPU embedding 延迟和显存。
- 每轮调用次数和估算成本。

## 运行记录

每次实验保存世界快照、事件序列、NPC 记忆、对话、模型配置和环境信息。人工评分另行填写，不与自动指标混合。

## 成功标准

- 玩家可以移动、选择 NPC、对话和重置世界。
- 关键世界状态只由规则层更新。
- 记忆能够跨轮次召回，且按 NPC 隔离。
- 至少完成 A 与 D 两个版本的对照。
- 结果能生成关系变化和延迟图表。
