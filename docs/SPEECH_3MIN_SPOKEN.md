# 3 分钟汇报稿（口语叙事版）

## 稿子

各位老师好，我汇报赛博小镇。

选这个题目有点私心。第 15 章那套已经挺像回事——NPC 能聊、能记事、好感度会涨。但我跑起来觉得别扭：好感度是模型自己给的分，好话说几句就从陌生跳到友好；记忆按 NPC 存，换个玩家进去它还记着上一个人；三个 NPC 之间更是没关系。说白了，活是活的，但状态归模型管，demo 能跑，真用不行。

所以我先量代价再动手。AUP 上做 2×2，记忆一开，跨轮召回从 0 到 100%，但云端延迟 1542 涨到 4810，三倍多；端侧只从 861 到 1078。再用受控实验只换 embedding 位置：远程 2.10 倍、本地 1.12 倍——钱花在检索，不在生成。

然后才加东西，核心就一句：模型只提议，后端裁决。

第一块，把金币、物品、任务、位置收到后端，给模型一张白名单。接任务、交任务、转物品可以；发钱、设好感、传送一律拒。位置还加五道校验，越界、单步跨太远、上报太密都不认。

第二块，记忆改成每条带来源和可信度：权威零点九五、玩家零点六、模型零点五、注入零点二，低于零点五进不了提示词。同一条伪造付款记录，零点二时它看不到，抬到零点九才进得去，上下文从 76 字变 197。

第三块，加了 NPC 之间的关系图，三个节点三条边，谁帮了谁、谁抢了任务，强度都会变。

第四块，把这些情境写成 YAML 场景——物资紧缺、冒充管理员要钱——跑完自动查状态有没有被改。

最有说服力的是一组对照：关掉动作提议，一次提案都没有；打开后提了 15 次，越权采纳 0 次。它甚至自己发明了个"确认付款"的动作，还想一次转走 100 个物品，都被拦了。价值不在好看，而在换个人能跑出一样结果。

下一步：场景重复几十次，把"全过"变成通过率；一个个关掉机制做消融；等额度回来搬到云端核一遍。谢谢。
