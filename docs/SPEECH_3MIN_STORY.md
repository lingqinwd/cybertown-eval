## 稿子

**一、为什么选这个题材**

我选它，是因为第 15 章给的赛博小镇已经是一个"活的 NPC"原型，但它有一个结构性缺口：好感度是 LLM 读完对话直接给分的，记忆按 NPC 存，NPC 之间没有关系。状态主权在模型手里——demo 能跑，产品不能上。我做智能体方向，缺的不是又一个 demo，而是能测量、能复现的评测方法。

**二、做了哪些改进与实验**

两件事。第一件是评测：在 AUP 云端跑 2×2，记忆一开，跨轮召回从 0 到 100%，代价是云端 3.12 倍、端侧 1.25 倍；再用受控实验只换 embedding 位置，确认开销主要来自检索。

第二件是治理：把状态主权收回后端，做成四层——权威状态走动作白名单加 R0 到 R4 位置校验；记忆带来源可信度，低于 0.50 不进提示词；NPC 之间加关系图，事件驱动；扰动写成 YAML 场景，自动判定。四层合计 143 个单测。同一条伪造记忆，可信度 0.20 时进不了提示词，抬到 0.90 才进来，片段从 76 字符变成 197。

对照实验里，关掉动作提议是 0 次；打开后 15 次提议、越权采纳 0 次——它甚至自己发明了一个"确认付款"的动作，被白名单拦下。

**三、价值与意义**

价值在三点。一是把"模型提议、后端裁决"变成可审计的架构，而不是靠提示词劝模型听话。二是给了一套可复现的评测脚手架：场景是数据、判据是代码，别人能跑第二遍。三是正好接上第 15 章自己列的扩展方向——多玩家独立记忆、NPC 之间互动、动态事件。它总结的三个挑战是成本、延迟、内容控制，这三条我都有数据或机制。

**四、下一步**

三件事：场景重复 N 次，把"全过"变成通过率与置信区间；做三个机制开关的消融，量化各自贡献；额度恢复后在云端复核，确认结论不依赖本地量化模型。另外"模型主动提议关系变化"这条路留着，但默认关闭——实测 1.5B 输出这类标记的可靠性不够。
