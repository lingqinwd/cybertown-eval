# 3分钟课堂汇报稿

大家好，我的结课项目题目是《CyberTown-Memory-Eval：基于记忆增强的可交互 AI NPC 赛博小镇》。

这个项目基于 Godot 4.5.2 的 2D 赛博小镇场景。玩家可以在场景中移动，靠近 NPC 后按 E 键进行对话。后端使用 FastAPI，NPC 回复由 DeepSeek 生成，记忆模式使用 WorkingMemory、SQLite 和 Qdrant 保存和检索对话信息。

我主要想研究一个问题：给 NPC 增加长期记忆后，它能不能更好地保持跨轮对话的一致性？这种能力会带来多少响应延迟？

实验采用消融对比。基线模式关闭长期记忆，也关闭进程内短期上下文；记忆模式开启 WorkingMemory、SQLite 和 Qdrant。两种模式使用相同的 Godot 场景、相同的 DeepSeek 模型、相同的 NPC 和相同的问题。

实验中，我先告诉李四：“我叫小林，正在做赛博小镇课程项目，请记住我的名字和项目名称。”之后重新询问她是否记得。记忆模式下，李四能够正确回答“小林”和“赛博小镇课程项目”；基线模式下，李四表示一时想不起来，需要我重新提醒。张三和王五则分别从多智能体开发、界面设计和视觉配色角度给出项目建议，说明 NPC 仍然能够保持角色差异。

目前每种模式记录了 6 次唯一对话。记忆模式平均端到端延迟是 4810 毫秒，最快 3630 毫秒，最慢 7979 毫秒，事实回忆成功率是 100%。基线模式平均延迟是 1542 毫秒，最快 1297 毫秒，最慢 2063 毫秒，事实回忆成功率是 0%。这说明长期记忆带来了约 3268 毫秒的平均额外等待，但换来了基线模式不具备的跨轮事实回忆能力。

项目的价值在于，它把大语言模型、持久化记忆和 2D 游戏交互放在了一个可以实际运行和测量的系统中。后续我会增加重复测试次数，记录结构化 CSV 指标，并进一步分析记忆召回次数与响应延迟之间的关系。最终成果包括 Godot 客户端、FastAPI 后端、记忆消融实验、部署文档和公开 GitHub 仓库。谢谢大家。
