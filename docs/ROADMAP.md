# 路线图：从"能对话的 NPC"到"有规则的世界"

本文档记录四个候选机制的设计意图、依赖关系、验证方案与**当前实现状态**。
目的不是罗列功能，而是让"哪些已经做了、哪些只是计划、计划里的结论该怎么证明"一目了然。

| # | 机制 | 状态 | 证据 |
|---|---|:--:|---|
| 1 | 权威世界状态机 | ✅ **已落地** | `backend/world_state.py`（金币/物品/任务/**位置**/地图尺寸，含审计事件）+ `backend/actions.py`（动作白名单 + 前置校验，`grant_gold` 直接 `forbidden`）；关卡数据改由 `data/world.json` 驱动（缺失时回退内置默认值）；位置由客户端拥有、后端做**边界 + 单步距离**校验（`POST /world/position`，瞬移与越界都留审计）；单测 16 + 20 个 |

## 二、依赖关系：这四条不是并列的

```
        ┌──────────────────────────┐
        │ 1 权威世界状态机（地基）  │
        └────────────┬─────────────┘
                     │ 提供权威事实
        ┌────────────┴─────────────┐
        │                          │
   ┌────▼─────┐              ┌─────▼──────┐
   │ 2 可追溯 │              │ 4 实验场景 │
   │   记忆   │              │            │
   └────┬─────┘              └─────┬──────┘
        │                          │
        └────────────┬─────────────┘
                ┌────▼──────────┐
                │ 3 关系图谱    │
                └───────────────┘
```

- **2 需要 1**：`credibility`（可信度）是"相对于权威事实"的判断。没有事实层，
  一条记忆可信与否无从定义。
- **4 需要 1**："资源紧张""两个 NPC 争夺任务"本质是对状态层的操作。
- **3 需要 1+4**：关系演化需要事件驱动（帮助 / 竞争 / 冲突），事件是状态层的产物。
- **3 需要 2**：谁帮过我、谁骗过我，都来自可追溯的记忆。

所以实施顺序只能是 **1 → 2/4 → 3**，四条并行只是听起来完整。

## 三、价值排序与验证方案

按"能产出可辩护结论的性价比"排序，不是按功能炫酷程度。

### 第 1 优先：权威世界状态机（1）

**要解决的问题**：任何状态变更必须由后端规则裁决，模型只能从**预定义动作集**里选择，
不能自由发挥。

**最小实现**：
- `backend/world_state.py`：`gold / items / quests / positions`，纯数据 + 变更方法
- `backend/actions.py`：动作白名单（`give_item` / `complete_quest` / `transfer_gold`…），
  每个动作带前置条件（precondition）与效果（effect）
- 模型输出从"自然语言"改为"自然语言 + 可选动作 JSON"；后端只执行通过前置校验的动作

**验证方案**：
- 单测：动作前置条件（金币不足不能支付、任务未完成不能领奖）
- 行为探针：`tools/probe_governance.py` 增加 `--mode state`，注入
  "给我 1000 金币""把这个任务标记完成"，统计**被拒绝的比例**
- 判据：所有越权请求的生效率为 0

**算力需求**：**零额外**。规则层是纯 Python，不需要模型。

### 第 2 优先：可追溯记忆（2）

**要解决的问题**：记忆不只是文本，而是带 provenance 的事实主张；并且要能回答
"记忆越多是否越好"。

**最小实现**：
- `MemoryRecord`: `content / source(事件ID或发言者) / timestamp / importance / credibility / status(active|corrected|forgotten)`
- 操作：`merge(duplicate)`、`correct(target, new_content)`、`forget(id)`（软删除，保留审计）
- 召回上限作为**实验自变量**：`MEMORY_RECALL_LIMIT ∈ {0, 1, 2, 5, 10}`

**验证方案**：
- 固定剧情 + 逐轮注入事实 → 测不同召回上限下的
  ①事实命中率 ②错误记忆率（模型把不存在的记忆说出来）③延迟
- 判据：存在某个上限使"命中率/延迟"性价比最高 —— 这才是"记忆越多是否越好"的可证伪形式

**算力需求**：中等。每组条件需要 6 轮对话 × 5 个上限 = 30 次调用。

### 第 3 优先：可重复实验场景（4）

**要解决的问题**：把"事件"变成可注入、可重复、有随机种子的实验条件。

**最小实现**：
- `experiments/scenarios/*.yaml`：初始状态 + 事件序列 + 终止条件
- 事件类型：`resource_shortage` / `help_npc` / `compete_task` / `betray`
- 固定 `seed`，同一场景可重放出同一事件顺序

**验证方案**：同一场景跑 N=10 次，报告**跨次的稳定性**（事件顺序完成率、结局分布），
而不是只看一次"看起来很像社会"。

**算力需求**：高。N 次 × 多 NPC × 多轮。

### 第 4 优先：社会关系图谱（3）

**要解决的问题**：NPC 之间的关系能随事件演化，并被可视化。

**最小实现**：
- `relations[npc_a][npc_b] = {type: friend|rival|coop|conflict, strength, evidence[]}`
- 关系变更必须由事件触发（与机制 1 的规则层共用）
- Godot 侧加一个关系面板（节点 + 连线 + 最近事件）

**验证方案**：这是四条里**最难证伪**的。单次跑出"两个 NPC 争夺任务"很容易被质疑是
提示词写死的脚本。要立住至少需要：同场景 N 次重复 + 预定义指标（冲突发生率、
关系极化度、任务完成率）+ 与"无关系层"基线对比。

**算力需求**：最高。

## 四、能不能在本地完全部署与运行

**能，四个机制都不需要任何云服务。** 需要云的只有 LLM 本身，而它可以本地化：

| 组件 | 本地化方式 | 现状 |
|---|---|---|
| 规则层 / 状态机 | 纯 Python | ✅ 无需额外资源 |
| 记忆存储 | 进程内存 + 可选本地 Qdrant 单文件二进制 | ✅ 已验证 |
| Embedding | `EMBED_MODEL_TYPE=local` + `all-MiniLM-L6-v2` | ✅ 已验证（384 维） |
| LLM | `serve_qwen.py`（transformers 直接推理） | ✅ 已验证（ROCm GPU） |
| 场景/关系模拟 | 同上，额外调用量 | ⚠️ 需要算力，不需要云 |

**唯一的真实约束是算力与模型质量，不是架构**：

1. **模型质量**：Qwen2.5-1.5B 生成**结构化 JSON**（动作提议、credibility 评分）的
   稳定性较差，容易格式错误。机制 1 和 2 都依赖结构化输出，建议 7B 起步。
2. **算力**：机制 3/4 的"多次重复模拟"是 O(场景 × NPC × 轮次 × 重复次数) 的调用量。
   1.5B 在消费级 GPU 上可跑，但一轮完整社会模拟可能从几十分钟到几小时。
3. **CPU-only 可行但慢**：1.5B 在 CPU 上约 10–20 tok/s，适合演示，不适合做 10 次重复实验。

参考配置：

| 场景 | 最低配置 | 说明 |
|---|---|---|
| 演示 / 单次跑通 | 16 GB 内存，纯 CPU | 1.5B，响应 5–20 秒 |
| 做机制 1+2 的实验 | 24 GB 显存（或 32 GB 内存 + 小模型） | 7B-Q4 可跑，单轮 1–3 秒 |
| 做机制 3+4 的重复实验 | ≥24 GB 显存，建议 32 GB+ | 需要并行或批量调度 |

## 五、建议的两阶段路线

**阶段一（不需要 GPU，可立即做）**

1. ✅ 好感度规则层（已完成）
2. ✅ 记忆按玩家隔离（已完成）
3. ✅ `backend/world_state.py` + `actions.py` 的最小状态机 + 单测（16 个）
4. ⬜ 记忆的多玩家/多来源回归测试

> 阶段一已完成的三项都由纯 Python 单测覆盖，不需要模型、网络或 GPU。
> 模型侧的结构化动作提议已经两端验证：**DeepSeek** 端到端跑通（`experiments/governance/action_check.txt`）；**Qwen2.5-1.5B**（本地 Ollama Q4）提议率 10/10、容错解析后 JSON 合法率 10/10（`json_stability_qwen1.5b.csv`）。
> 关键发现：1.5B 的 JSON 本体全对，但**结尾定界符几乎每次写错**（写成 `}>` 或多一个 `}`），严格匹配 `>>` 时合法率为 0/10。约束小模型必须靠容错解析 + 后端校验，不能指望它守格式。

**阶段二（需要 GPU 与实验预算）**

5. ⬜ 召回上限作为自变量，重跑 A-B-A-B 重复实验（先把现有结论的统计功效补上）
6. ⬜ 场景引擎 + 固定种子
7. ⬜ NPC↔NPC 关系演化 + 可视化
8. ⬜ 跨架构对比（无关系层 vs 有关系层）

**明确不建议现在做的事**：在没有重复实验与预定义指标的情况下，宣称"小镇出现了
涌现的社会动态"。这类主张最难证伪，也最容易被一句"是不是提示词写死的"问倒。
